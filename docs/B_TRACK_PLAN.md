## 階段 2:診斷失敗原因(2-3 天)

在換方法之前,先搞清楚**為什麼現在會失敗**。三個問題:

### 2.1 根因的殘差到底排第幾?為什麼被蓋過?

排在根因前面的那些 sensor 是什麼?

- **是根因的下游** → 傳播蓋過根因 → 圖修正/剝除應該有用(但目前沒用,查公式)
- **與根因無關** → 有其他異常源,或殘差本身有雜訊 → 需要更好的殘差估計
- **是同一組製程相關的 sensor** → 可能是共因結構,需要不同處理

```python
# 對每個真根因,列出排在它前面的 sensor,並標註它們與根因的圖上關係
```

**這是最關鍵的診斷** —— 它決定要往哪個方向改進。

### 2.2 時序解析度是否足夠?

```python
t = pd.to_datetime(df['START_DATETIME'])
print('unique 時間戳:', t.nunique(), '/', len(t))
```

若大量 wafer 時間戳相同,onset 會大量並列 → 時序證據失效。
**這可能就是時序 patch 在真實資料上無改善的原因。**

### 2.3 異常是漸進還是突發?

畫出真根因的殘差時序曲線。若異常是**突發且與下游幾乎同時**,
時序證據本就無效;若是**漸進**,則 onset 的偵測門檻需要調整。

## 階段 3:換工具(不受 MT-NGC 綁定)

依階段 2 的診斷結果,選擇對應的工具。**以下方法皆與論文無關,純以效果為準。**

### 3.1 若問題是「殘差估計不準」

- **更強的預測器**:LightGBM / XGBoost per-sensor 迴歸,取代 MLP
  → 殘差更準 → 根因更突出。這是最直接的改善,且實作成本低
- **多模型集成**:多個預測器的殘差取共識,降低單一模型的偏差

### 3.2 若問題是「傳播蓋過根因」

- **時序領先分析**:Granger 因果或 cross-correlation 找「誰先動」
  (與 MT-NGC 無關,可獨立實作)
- **變點偵測**:對每個 sensor 做 changepoint detection,取最早的變點
  (ruptures 套件,成熟穩定)

### 3.3 若問題是「異常訊號本身弱」

- **對比學習式異常偵測**:Normal vs Abnormal 的分布差異,而非預測殘差
- **統計檢定**:對每個 sensor 做 Normal vs Abnormal 的分布檢定(KS test),
  最顯著的即候選 —— **這是最簡單的 baseline,而且必須先做**

### 3.4 必做:建立簡單 baseline 對照

**目前缺少「不用因果圖的簡單方法」作為對照。** 沒有它,無法判斷
複雜方法是否真的有價值。至少要有:

| baseline | 說明 |
|---|---|
| 單變量統計檢定 | 每個 sensor 做 Normal vs Abnormal 的 KS/t 檢定,依 p 值排序 |
| 變異數比 | Abnormal 變異數 / Normal 變異數 |
| PCA 重建誤差 | 標準的無監督異常偵測 baseline |
| Isolation Forest | 同上 |

**若這些簡單方法的 recall@10 與 MT-NGC 相當,那就用簡單的** ——
B 軌的目標是成果,不是方法新穎性。
