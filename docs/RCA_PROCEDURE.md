# 半導體異常根因分析流程

**版本**:2026-10-27(前版 2026-08-11)
**適用範圍**:case1、case2、FD_rawdata 及同型態的 FD 資料
**核心方法**:邊際 Welch t 檢定 + bootstrap 穩定度驗證
**輔助**:因果圖分組、合取規則萃取

---

## 一、流程總覽

```
原始 FD 資料 (wafer × 參數,含 Normal/Abnormal 標記)
        │
        ├─ 步驟 0a  NA 前處理（丟含缺值的列，高缺值參數改丟欄）
        │
        ├─ 步驟 0b  參數縮減（依記憶體預算決定保留數）
        │
        ├─ 步驟 1   MT-NGC 訓練 → 因果圖（僅供分組，見第五節）
        │
        ├─ 步驟 2   候選集（同事的 GNN pipeline，或 Welch 排名）
        │
        ├─ 步驟 3   逐參數 Welch t 檢定 → 主排名
        │
        ├─ 步驟 4   bootstrap 穩定度驗證 → 最壞名次
        │
        ├─ 步驟 5   效果量門檻校準（標籤置換）
        │
        ├─ 步驟 6   因果圖分組（把候選聚成組）
        │
        ├─ 步驟 7   合取規則萃取（多變量分析）
        │
        └─ 步驟 8   輸出 HTML 報告 → 交付工程師
```

**重要**:本流程**不含**獨立的「根因推論」階段。異常偵測與根因定位在此
方法中是同一個步驟 —— Welch 排名最前者即為根因候選。因果圖只用於**分組
與排查順序**,不用於推論根因。原因見第五節。

---

## 二、逐步說明

### 步驟 0a|NA 前處理

`groupby().mean()` 會靜默跳過 NaN,含缺值的 wafer 仍會產生數值,只是那個
平均是用較少的點算的,而且在後續檢定裡與其他 wafer 等權重比較。這比報錯
更危險,因為結果看起來正常。

處理策略分兩層:

1. 缺值比例超過門檻(預設 50%)的參數 → **丟欄**。若某 sensor 有 93%
   缺值,丟列會把 93% 的資料砍光。
2. 其餘含缺值的列 → **丟列**。

**必須回報 wafer 存活情況,不只回報列數。** 分析單位是 wafer;丟掉的列
若剛好集中在某幾片,那幾片就整片消失。異常樣本本來就少,少一片對 Welch t
的影響遠大於少幾十列。

**若異常批被丟棄的比例明顯高於整體,不要接受分析結果。** 那表示缺值本身
帶訊號(感測器在異常時斷線),丟列等於系統性移除訊號。此時要用
`dropna: "none"` 跑一次對照,兩種結果一致才能信。不一致的話,「哪些參數
在哪些 wafer 缺值」這個模式可能比參數值本身更能指出根因。

### 步驟 0b|參數縮減

MT-NGC 對每個 target 各建一個 MLP,總參數量約 `N² × lookback × hidden`:

| N | 含 Adam 動量 |
|---|---|
| 200 | 0.09 GB |
| 500 | 0.54 GB |
| 1000 | 2.15 GB |
| 5000 | 53.64 GB |

5000 個參數時模型參數量 48 億,**超過 int32 上限(21.47 億)兩倍以上**,
大小計算溢位會配置到 NULL,Windows 顯示「指令位置 0x00000000」。這不是
bug,是架構的本質限制。

縮減分四步,前三步免費(不需任何假設):

1. 常數欄(變異數為 0)
2. 近常數欄
3. 重複欄(|相關| > 0.999)
4. top-K —— 這一步才是取捨

**top-K 不可只用變異數排序。** 實測:一個真根因在 Normal 變異數排
2446/5000,但 Welch 排第 3。好的根因特徵正是「正常時安靜、異常時偏移」,
變異數篩選會漏掉它。

兩種做法:
- 有候選清單 → 候選無條件保留,其餘用變異數補滿
- 無候選清單 → `--mode welch`,依 |Welch t| 排序

**後者用到標籤,之後不可主張「圖未看過標籤」。** 對 B 軌可接受,因為圖
只用於分組已由 Welch 排出的候選,不是獨立的發現機制。但這件事必須寫進
方法說明。

### 步驟 1|MT-NGC 訓練

訓練資料用**原始檔**,不用 NA 清理後的檔。清理會在時間軸上打出破洞,而
lookback 視窗會跨過破洞把不相鄰的時點當成相鄰 —— 那正是 `segment_lengths`
要避免的污染。

config 以 `data.train_csv`(訓練,原始或縮減檔)與 `data.csv`(分析,
清理檔)分開指定。兩者共用一個路徑曾造成實際的崩潰。

兩種模式:
- `average`:多個 seed 的權重平均
- `stability`:區塊子抽樣 + top-k 二值化 + 邊出現頻率矩陣

**穩定度選擇的輸出可跨列比較,原始權重不行。** 圖的 seed 間一致性實測僅
59%(case1)/ 67%(FD),所以單次訓練的圖不應直接採用。

### 步驟 3|Welch t 檢定(主排名)

```
t = |mean_abnormal − mean_normal| / sqrt(var_n/n_n + var_a/n_a)
```

分子是位移量,分母是該位移的不確定度。依 t 由大到小排序即為主排名。

**為何選 Welch 而非 KS**:KS 對分布形狀敏感,樣本少時單一離群 wafer 即可
改變結果。實測(bootstrap 200 次)顯示 KS 在 case1 雖取得單次滿分,但其中
一個真根因僅 13.5% 的重抽下進得了 top-10 —— 該滿分為抽樣運氣。Welch 在
三個 case 六個真根因上 `in_top10` 均為 100%。

### 步驟 4|bootstrap 穩定度驗證

重抽 wafer 200 次,每次重算排名,取每個參數名次的 95% 分位(`rank_p95`),
即「換一批 wafer 時最差會排到第幾名」。

**這是決定交付承諾的數字**,不是單次排名。

已驗證結果:

| case | 真根因數 | 各根因 rank_p95 |
|---|---|---|
| case1 | 2 | 2, 3 |
| case2 | 2 | 1, 2 |
| FD_rawdata | 3 | 1, 4, 5 |

**未解決的不一致**:FD_rawdata 在 `baseline_stability.py` 下得到
`[6, 5, 1]`,在驗收時得到 `[1, 4, 5]`。兩者的最大值分別是 6 與 5,原因
未定位。承諾採保守值。

**承諾:排查前 6 個參數。**

### 步驟 5|效果量門檻校準

以標籤置換建立虛無分布,給出兩個門檻:
- **全域門檻**:全參數最大 |d| 的 95% 分位(含多重比較校正)
- **單參數門檻**:混合分布的 95% 分位(未校正)

報告兩者,不合併。

### 步驟 6|因果圖分組

以 `edge_k`(每列保留的邊數)與 `min_concentration`(列最大值 / 列總和)
二值化因果圖,再取連通分量,每組指定錨點。

`min_concentration` 取代了早期的 `min_edge_ratio` —— 後者相對於列最大值,
而最大值永遠通得過自己的門檻,等於沒有作用。

**組別順序即排查順序**,不另外依 Welch 重排。

**分組可能把某個參數往後推。** 實測反例:P02 由第 2 位移到第 4 位,
P06 由第 3 位移到第 5 位。不可宣稱「分組不會讓任何參數變差」。

**已知限制**:在某些資料集上分組完全不起作用。最近一次實測
`p=300 g=10 cb=1` —— 10 個分組每組只有一個參數,組合數 1,因果圖對分組
沒有任何貢獻。可能是 `edge_k` / `min_concentration` 太嚴,也可能候選參數
之間在圖上本來就沒有邊。此時步驟 7 的多變量分析失去意義。

### 步驟 7|合取規則萃取(多變量分析)

每組選一個參數切一刀,組成合取規則(「P01 > a 且 P07 < b 時判為異常」)。

兩種搜尋:
- **序貫**:依組別順序貪心加入,增益低於門檻即停
- **全組合列舉**:窮舉每組取 1~m 個參數的所有組合

**兩者空間互不包含**,各有盲點,任一方都可能較好。

**以訓練集指標決定採用者,驗證集僅用於報告。** 若改看驗證集挑,等於對
驗證集過擬合,其數字將不再是無偏的效能估計。

指標定義(容易混淆,此處固定):
- 解釋比例 = Recall = 命中的異常片 / 全部異常片
- 誤報率 = FPR = 被誤判的正常片 / 全部正常片
- 精確率 = Precision = 命中的異常片 / 全部被判為異常的片

**解釋比例與誤報率不是 Precision 與 Recall。**

**合取條件只會使解釋比例下降、精確率上升**,故不以解釋比例當增益指標,
預設用 F1。

實作為前綴共享的深度優先搜尋 + 可容許上界剪枝(F1 ≤ 2R/(1+R),R 單調
不增)。最佳解不會被剪掉。實測 10¹² 個名目組合可在 1 秒內完成。

**實作細節**:增益比較必須與 `eval_rule` 一樣四捨五入到小數 3 位。
不捨入時,增益落在門檻邊界(如 0.0196 對 0.020)會讓停止判斷相反,序貫
與列舉兩張表就不再可比。

末尾有隨機對照:隨機挑同數量的參數組規則,比較 F1 分布,給出 p 值。

### 步驟 8|輸出與交付

- `*_report.txt` 完整文字報告
- `*_ranking.csv` 參數排名(含 t 值、`rank_p05/median/p95`)
- `*_rules.csv` 所有規則與訓練/驗證指標
- `*_result.json` 結構化結果(含各步驟耗時)
- `*.html` 自含的報告(無外部資源,內嵌 SVG)

**交付說明必須包含**:

> 本方法找出的是「與正常批差異最大的參數」,無法區分根因與被其波及的
> 下游參數。輸出用於將排查範圍由 N 個縮小至 6 個,不取代工程師判斷。

## 四、輸出的解讀方式

| 欄位 | 意義 | 怎麼用 |
|---|---|---|
| 名次 | 單次執行的排名 | 參考,不作為承諾依據 |
| `rank_p95` | 最壞情況名次 | **決定要看前幾個** |
| 進前 6 的比例 | bootstrap 中進入 top-6 的頻率 | 低於 80% 者可信度不足 |
| 位移(標準差倍) | 偏移量 | 判斷實務顯著性 |
| 訓練F1 | 規則挑選依據 | 只用於挑選 |
| 驗證各欄 | 效能估計 | 對外報告用這組 |

**判讀原則:只看最差名次。** 排名第 1 的參數命中對排查沒有幫助 ——
工程師事先不知道哪個猜對了,仍需一路檢查到最後一個真根因為止。決定排查
工作量的是最差名次,不是最好名次。

## 五、為何不含獨立的「根因推論」階段

已測試多種以因果圖從候選集推論根因的方法,全部未通過驗證。**對照組是
同構節點重排** `A[π][:,π]` —— 它保留邊數、無環性、後代分布與入度分布,
是唯一正確的虛無對照。

| 用法 | 圖的角色 | 結果 |
|---|---|---|
| 殘差修正(`parent_adj`、迭代剝除) | 修正分數 | 無改善或更差 |
| 條件式預測(task2b + HistGB) | 決定條件變數 | 真圖劣於重排圖(case1 11 vs 3;FD 17 vs 11) |
| 拓樸硬過濾 | 剔除有祖先的候選 | 砍掉真根因,三個密度全否決 |
| 拓樸軟排序 | 依祖先數重排 | 勝過重排圖(5 vs 9),但劣於原順序(5 vs 3) |

**早期的對照組設計是錯的**:用隨機重抽父節點,而隨機有向圖多半有環,
後代排除把父節點清光(真圖 16/24 對重排圖 2/24),那個比較實際上是
「有條件化對沒條件化」,不是「真圖對假圖」。改成節點標籤置換後驗證:
邊數 66/66、後代配對 171/171、可用父節點 23/23。

**圖本身是可靠的**:配對 R² 檢定顯示真圖預測顯著優於同構重排圖(真圖
較佳 7 個 / 較差 0 個,符號檢定 p = 0.0156,平均 R² 0.6921 對 0.5198)。

**失效原因**:條件式方法中,異常訊號強度與預測器品質成反比 —— 圖越準,
模型越能用父節點正確預測根因的偏移,殘差反而變小。拓樸方法中,真根因在
圖上並非位於上游。

**估計目標不匹配**:因果圖估的是**條件依賴結構**,根因分析要的是
**邊際分布位移**。兩者不是同一個量。

**推測的根本落差**:工程師標記的「根因」是可調整、可歸責、具物理意義的
參數;因果圖找的是統計上最上游的變數,可能是無人會去調整的環境量或前置
條件。

**適用邊界**:上述結論僅適用於**根因訊號已飽和**的資料 —— 即真根因本身
即為邊際偏移最大者。不可推廣為「因果圖對根因分析無用」。若遇到傳播效應
強、根因被下游掩蓋的案例,條件式方法仍值得重新評估。

## 六、已知限制與後續方向

**限制**

1. 無法區分根因與下游參數(見第五節)
2. 僅對平均值位移敏感;變異型異常(參數卡住、震盪變大而平均未動)會漏掉
3. 承諾的「前 6 個」基於三個 case 六個根因,樣本數小
4. FD_rawdata 的 `rank_p95` 有未解決的不一致(見步驟 4)
5. 因果圖分組在部分資料集上完全不起作用(見步驟 6)
6. **統計能力的根本限制**:T=175 列資料配 N=300 個參數,每個 target
   要擬合 57,600 個參數 —— 每個觀測值 427 個參數。模型幾乎完全由正則化
   與初始化決定。這直接解釋了圖的 seed 間一致性只有 59–67%。即使 N 砍到
   60,仍是每觀測值 85 個參數。

**後續方向**

- 針對限制 6:`lookback` 由 3 降到 1、`hidden_dim` 由 64 降到 16,或改用
  線性 group lasso 取代 MLP。`lookback=1` + `hidden=16` + N=150 時每個
  target 只有 2,400 個參數,每觀測值 18 個 —— 這個數量級才有可能學到
  真的結構
- 若出現傳播效應強的新案例,重新評估條件式方法
- 與工程師確認「根因」的定義,釐清第五節推測的落差是否成立
- 累積更多案例後重新校準 `top-k` 承諾值
- 定位 FD_rawdata 的 `rank_p95` 不一致
